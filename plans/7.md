# Plan for #7: Add readiness and liveness probes, run two replicas

## Goal
Configure Kubernetes to keep traffic on healthy application pods and restart
unhealthy containers, while running two replicas for basic availability. The
application API and environment contract do not change.

## Dependencies (confirmed / plausible / open), each with change: yes | no
- **Confirmed — change: yes:** `k8s/deployment.yaml` currently sets
  `spec.replicas: 1`; set it to 2 and add HTTP readiness and liveness probes.
- **Confirmed — change: yes:** `.github/instructions/k8s.instructions.md` states
  the health endpoint is `GET /health` on container port 3000; probes must use
  that path and port.
- **Confirmed — change: no:** `src/app.ts` already serves `GET /health`, so no
  application route is needed.
- **Confirmed — change: no:** `src/config.ts` and `k8s/configmap.yaml` need no
  new or changed environment variable.
- **Plausible — change: no:** `README.md` may mention deployment behavior, but
  the ticket is fully represented by the manifest and existing operational
  documentation; verify whether a deployment note is needed during
  implementation.
- **Open — change: no:** GitHub issue text is unavailable because issues are
  disabled in this fork; the repository facilitator guide is the available
  ticket specification.

## Tests
- No application unit test is needed because `/health` is already covered by
  `test/app.test.ts`.
- Verify the manifest through `npm run verify` and the pipeline’s rollout,
  pod-stability, smoke, and browser checks.

## Environment contract
No environment variables are added or changed. Existing metrics settings in
the worktree are unrelated pre-existing changes and must be preserved.

## Risks
- A wrong path or port would leave both replicas unready and fail rollout.
- An overly aggressive probe configuration could cause restart loops; use
  conservative Kubernetes HTTP probe defaults consistent with the small app.
- Pipeline failures may occur in rollout, stability, smoke, or browser gates
  even though unit tests and build remain green.

## Open questions
1. None blocking implementation; `/health` on port 3000 is mandated by the
   repository instructions and the facilitator’s #7 specification.

## Decisions
- Proceed with `/health` on the named `http` container port (3000), using
  conservative readiness and liveness timings.
