# Plan for #4: Filter runs by vehicle on the web page

## Goal
Add a vehicle filter control to the runs page so users can request and view only
runs for the selected vehicle. Existing run listing, creation, and API behavior
remain unchanged; the page continues to show all runs when no vehicle is selected.

## Dependencies (confirmed / plausible / open), each with change: yes | no
- **confirmed** — `public/index.html`: page markup and `load()` currently fetch
  `/api/runs` without a filter; add the control and wire its value into the
  existing request/render flow. **change: yes**
- **confirmed** — `src/app.ts` and `src/runs.ts`: `GET /api/runs?vehicleId=`
  already passes an exact vehicle ID to `RunStore.list`; no API change needed.
  **change: no**
- **confirmed** — `e2e/smoke.spec.ts`: existing Playwright page tests establish
  accessible locator conventions and seeded-run assumptions; add browser coverage
  for filtering. **change: yes**
- **confirmed** — `test/app.test.ts`: API filtering is already covered; retain it
  as regression coverage. **change: no**
- **plausible** — `README.md`: no user-facing page-control documentation is
  currently present; verify after implementation whether a usage note is needed.
  **change: no**
- **open** — The disabled upstream issue tracker prevents reading the exact
  acceptance wording for #4; implementation will follow the stated request and
  existing API contract.

## Tests
- `e2e/smoke.spec.ts`: add a Playwright test that loads the page, selects or
  enters a vehicle filter, and asserts only that vehicle's rows are displayed.
- `test/app.test.ts`: no change; the existing API filter test remains sufficient
  for the unchanged backend contract.

## Environment contract
No environment variables, configuration, Kubernetes manifests, or README
environment-table entries are added or changed.

## Risks
- The browser test could become flaky if it asserts before the filtered fetch
  completes; use Playwright-visible row assertions that wait for the result.
- Existing add-run behavior must continue to reload the currently filtered view
  (or preserve the page's established all-runs behavior if no filter is active).
- Pipeline risks are limited to the TypeScript/unit/build job and the deployed
  Playwright browser step; API, rollout, stability, and smoke checks should be
  unaffected.
